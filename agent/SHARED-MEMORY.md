# حافظهٔ مشترک سوسیسا: یه منبع حقیقت برای همه

> نسخهٔ ۱، دوشنبه ۱۱ آبان ۱۴۰۵ (تصمیم ممضی). **هر Claudeی که روی سوسیسا کار می‌کنه** این رو اول کار می‌خونه: ایجنت مدیر پروژه، ادمین پیج، چت پروژهٔ سوسیسا، چت Claude، Cowork، Claude Code (ابری یا لپ‌تاپ). هدف: هر تغییری هر جای پروژه همون لحظه یه جا ثبت بشه و بقیه از همون‌جا بخونن.

## ۱. منبع حقیقت = همین مخزن

برد اصلی و برد محتوا هر دو مستقیم از `board-data` می‌خونن؛ پس هر چیزی که با ابزار ثبت بشه حدود ۲۰ ثانیه بعد تو هر دو برد و برای همهٔ سطح‌ها دیده می‌شه.

## ۲. ترتیب خوندن اول هر کار
1. `kb/live.md` (وضعیت امروز)، 2. همین فایل، 3. `kb/BANK.md`، 4. `agent/knowledge/README.md` و ماژول‌های همون کار، 5. خود تسک یا محتوا با `board.py show` یا `content.py show`.
بدون شل: نسخهٔ وب همین‌ها روی GitHub Pages (`…/Susisa-projectboard/kb/live.md` و `…/agent/SHARED-MEMORY.md`).

## ۳. هر سطح چطور می‌نویسه
| سطح | نوشتن | امضا (`--by` در `content.py`، و آخر کامنت‌ها) |
|---|---|---|
| ایجنت مدیر پروژه (زمان‌بندی، اکانت گلیچ‌لب) | مستقیم با ابزار، commit و push | `مدیر پروژه` |
| ادمین پیج (بخشی از همون اجراها) | مستقیم با ابزار | `ادمین پیج` |
| Cowork، Claude Code ابری، چت Claude با شل | مستقیم با ابزار؛ push خودکار (تصمیم ممضی) | `چت Cowork (ممضی)` یا `Claude Code (امیرحسین)` و… |
| Claude Code روی لپ‌تاپ ممضی | اگه ابزار و دسترسی داره مستقیم؛ وگرنه `_agent/inbox/` ولت | `Claude Code لپ‌تاپ` |
| چت بدون شل (موبایل، چت ساده) | بلوک تحویل (قالب دستورالعمل پروژه) یا یه خط «رویداد تازه» که کاربر کامنت می‌کنه | — |

**قاعدهٔ «همون لحظه»:** هر تصمیم، فایل نهایی، تاریخ تازه، کانسپت، سناریو، کپشن یا عددی که تو هر چت به نتیجه رسید، **همون موقع** روی برد ثبت می‌شه (نه آخر روز، نه با «آپدیت کن»). تصمیم و دانش هم یه خط زیر «رویدادهای تازه» `kb/BANK.md`. ایجنت مدیر پروژه هر اجرا اون خط‌ها رو به ماژول‌ها می‌بره و پاکشون می‌کنه.

## ۴. تقسیم کار روی برد محتوا (تصمیم ممضی، ۱۱ آبان)
- **کانسپت، سناریو، اسکریپت، استوری‌بورد، شات‌لیست، کپشن** رو چت‌ها حین کار با آدم‌ها ثبت می‌کنن (با `content.py --by "<سطح>" set …`).
- **تحلیل‌ها** رو ادمین پیج خودکار ثبت می‌کنه: اینسایت (`insight.h24.*`، `insight.h72.*`، `insight.last.*`، `insight.src`، `insight.analysis`، `insight.lesson`)، کامنت تحلیل، هشدار، و پنل «یادداشت Claude» (`ai`).
- ادمین پیج **پیش‌نویس** همهٔ فیلدها رو هم می‌تونه بنویسه (تصمیم ممضی)، ولی:
  - روی محتوای `hold` هیچ‌چیز (ابزار خودش جلوشو می‌گیره).
  - هیچ‌وقت «تأیید شد» (ok) نمی‌زنه؛ فقط `draft` یا `review`.

## ۵. تداخل: نسخه‌ها کنار هم، انتخاب با آدم
- **پیش‌فرض: آخرین نوشته برنده‌ست.** ولی متن قبلی از بین نمی‌ره: `content.py` و خود برد محتوا، بازنویسی text، tags یا prompt بخش‌های کانسپت، سناریو، استوری‌بورد، برگهٔ ضبط، کپشن، تدوین و هماهنگی رو تو «نسخه‌های دیگه» (`<بخش>.alts`، تا ۱۰ نسخه، با اسم نویسنده و ساعت) نگه می‌دارن.
- اگه اون بخش «تأیید شد» بود و متنش عوض شد، خودکار برمی‌گرده به «منتظر تأیید» تا آدم یکی رو نهایی کنه.
- انتخاب: تو برد محتوا زیر هر بخش «نسخه‌های دیگه» ← «این بشه اصلی»؛ یا `content.py --by "<نام>" pick <id> <بخش> <n>` (۱ = تازه‌ترین). دیدن: `content.py alts <id>`.
- نهایی شدن = تأیید آدم (ممضی، امیرحسین یا امیررضا از طریق امیرحسین) با دکمهٔ «✓ تأیید».

## ۶. قاعده‌های ایمنی نوشتن
- `board-data` رو دستی ویرایش نکن؛ ابزارها قبل از هر نوشتن آخرین نسخه رو از سرور می‌گیرن و اگه push رد شد دوباره امتحان می‌کنن.
- قبل از push روی main: `git pull --rebase origin main`.
- محتوای `hold` (متوقف به دستور ممضی): نه نوشتن، نه پیگیری، نه سؤال، تا خود ممضی بگه. فقط ممضی می‌تونه با `--force` استثنا بده.
- مبلغ، قرارداد، پرداخت، توکن، رمز، اطلاعات شخصی مشتری: هیچ‌جای مخزن.
- عدد بدون منبع و تاریخ نه. حدس رو «فرضیه» بنام.

## ۷. رشد دانش همه
- هر سطح آخر کارش، درس و روش تازه رو یا مستقیم (`14-learnings.md`، `kb/METHODS.md`) یا با خط «رویداد تازه» ثبت می‌کنه.
- ایجنت مدیر پروژه هر اجرای کامل صبح درس‌ها رو به ماژول‌ها می‌بره (ماژول ۲۲)؛ پس فردا همهٔ سطح‌ها با دانش امروز شروع می‌کنن.
- ادمین پیج یافته‌های داده رو تو `kb/instagram/` و ماژول ۲۹ نگه می‌داره.
