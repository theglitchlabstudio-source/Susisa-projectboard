# ۲۳. انتشار در برندبوک و فایل‌های خوانا

> دستور تیم (۱۶ مهر ۱۴۰۵): هر تسک برندبوک و هر تسک مرتبط با برندبوک آخرش گام «افزودن به برندبوک (Claude)» دارد و **خود ایجنت** خروجی را با قالب و قواعد برند در برندبوک زنده می‌نویسد. کارهای تمام‌شدهٔ قبلی هم باید به برندبوک برسند. و خروجی‌ها فقط Markdown نباشند؛ نسخهٔ خوانا و قابل چاپ هم لازم است.
> برندبوک زنده: https://theglitchlabstudio-source.github.io/Susisa-Brandbook/ (مخزن theglitchlabstudio-source/Susisa-Brandbook، داده در `data/chNN.js`). ابزار: `python3 tools/brandbook.py`.

## ۱. کی منتشر کنیم
- تسک برندبوک (فیلد `bb` دارد) **تمام شد** یا ممضی خروجی‌اش را تأیید کرد ← همان اجرا منتشر کن.
- تسک در جریان است ولی خروجی قابل‌اتکایی دارد (پیش‌نویس تأییدشده توسط مالک) ← با وضعیت `draft` منتشر کن.
- تصمیم تازهٔ ممضی که یک بخش را عوض می‌کند (مثلاً قرمز نهایی) ← همان بخش را به‌روز کن.
- هر بار که منتشر کردی: `board.py check <id> done "افزودن به برندبوک"` و یک کامنت کوتاه روی تسک: «گذاشتمش تو برندبوک، فصل … بخش …» + لینک `…/Susisa-Brandbook/#/ch/<n>`.

## ۲. کجا منتشر کنیم
1. `python3 tools/brandbook.py chapters` ← بخشی که `task` آن همین تسک است اولویت دارد.
2. نبود ← فصل `bb` تسک؛ بخش موجودی که موضوعش همین است را به‌روز کن، وگرنه بخش تازه با شمارهٔ بعدی (`--title` لازم).
3. فصل ۱ (Raw Brand Notes) و هر چیز حساس (مصاحبه، پروپوزال، مالی، نقل‌قول خصوصی امیررضا) **منتشر نمی‌شود**؛ فقط خلاصهٔ غیرحساس یا «در ولت تیم».

## ۳. چطور بنویسیم (قالب و قواعد)
- منبع حقیقت: فایل خروجی تسک (ضمیمهٔ برد یا ولت)، تحویل دستیار تسک، کامنت‌های تصمیم ممضی. حدس نزن؛ چیزی که نیست را «باز» بنویس.
- **نوع گزاره** را طبق بخش ۰.۳ برندبوک مشخص کن: واقعیت، ادعای شرکت، ورودی بنیان‌گذار، تفسیر، فرضیه.
- لحن: فارسی روشن و کوتاه، جمله‌های قاعده‌ای («این کار را بکن / نکن»)، مثال درست و غلط. برندبوک سند مرجع است، کمی رسمی‌تر از کامنت‌های برد ولی بدون پیچیدگی.
- بدون کد تسک در متن (فیلد `--task` جدا ثبت می‌شود)، بدون مبلغ، بدون اسم فایل‌های داخلی.
- ساختار پیشنهادی هر بخش: یک پاراگراف «چیست و چرا» ← قاعده‌ها (فهرست) ← جدول مشخصات اگر لازم است ← «درست / غلط» ← !! نکتهٔ هشدار ← «منبع: …».
- دارایی بصری (رنگ، لوگو، فونت، الگو، تابلو، منوی تلویزیون): قالب ماژول ۱۸ بخش ۱۲. رنگ‌ها با بلوک پالت:
  ```
  ```palette
  قرمز سوسیسا | #CC0212 | لوگو، تیتر، دکمه
  ```
  ```
  و کنتراست (ماژول ۱۸: قرمز #CC0212 روی کرم #FAE089 فقط ۴٫۴۹ است؛ برای متن ریز رد می‌شود).
- وضعیت (`--st`): `final` مصوب ممضی · `early` زودتر از برندبوک انجام و مصوب شده · `draft` پیش‌نویس · `open` هنوز کار نشده · `later` بعد از افتتاحیه.

## ۴. دستورها
```
python3 tools/brandbook.py chapters                 # نقشهٔ فصل‌ها و بخش‌ها
python3 tools/brandbook.py show 6                   # متن فعلی فصل به Markdown
# متن بخش را در /tmp/bb.md بنویس (پاراگراف، - فهرست، > نقل، !! نکته، !!! هشدار، جدول، ### زیرتیتر، ```palette، منبع: …)
python3 tools/brandbook.py upsert 6 6.2 --md /tmp/bb.md --st final --task s2b
python3 tools/brandbook.py log "فصل ۶: رنگ‌های نهایی و کنتراست ثبت شد"
python3 tools/brandbook.py save "فصل ۶ رنگ"
python3 tools/board.py check s2b done "افزودن به برندبوک"
python3 tools/board.py comment s2b "گذاشتمش تو برندبوک، فصل هویت بصری بخش رنگ: https://theglitchlabstudio-source.github.io/Susisa-Brandbook/#/ch/6"
```
`save` قبل از push همهٔ فصل‌ها را چک می‌کند؛ اگر فصلی خراب باشد ذخیره نمی‌کند.

## ۵. بک‌فیل (کارهای قبلی)
تا وقتی تسک برندبوکی هست که تمام شده ولی گام «افزودن به برندبوک» تیک نخورده، در هر اجرای کامل ۳ تا ۵ تای آن‌ها را منتشر کن (اول فصل‌های نسخهٔ افتتاحیه: ۰، ۲ تا ۶، ۹، ۱۰). تسک‌هایی که خروجی محتوایی ندارند (جلسه، تنظیمات فنی، پیشنهاد مدیریتی) ← فقط تیک بزن و در کامنت بنویس «خروجی برندبوکی نداشت».

## ۶. فایل‌های خوانا (برای همهٔ خروجی‌ها، نه فقط برندبوک)
- هر سند `.md` که برای تیم می‌سازی را با `board.py attach <id> file.md` ضمیمه کن؛ ابزار خودش نسخهٔ خوانای `.html` (راست‌به‌چپ، وزیرمتن، آمادهٔ چاپ و PDF) را هم کنارش می‌گذارد. نسخهٔ جدید = همان نام ← نسخه‌دار می‌شود.
- برای Word: `python3 tools/render.py file.md --docx` و بعد `attach` همان .docx.
- پالت، تایپوگرافی، کیت لوگو: علاوه بر md، صفحهٔ مطالعه‌ای با نمونهٔ بزرگ رنگ/فونت بساز (بلوک ```palette در render.py خودکار نمونه، HEX، RGB و جدول کنتراست می‌سازد) تا مستقیم قابل استفاده در برندبوک باشد.
- گزارش‌ها: `report.py weekly --analysis …md --save` (بخش «گزارش کار» برد).
