# ۲۸. حافظهٔ خودکار کار، کلمهٔ رمز «ثبتش کن»، تأیید چهارمرحله‌ای امیررضا

> دستور ممضی (آقا Z) و امیرحسین (فتو)، دوشنبه ۴ آبان ۱۴۰۵. برای **همهٔ** Claudeها: ایجنت مدیر پروژه، دستیار پروژه (susisa-assistant)، Claude Code روی لپ‌تاپ‌ها، Cowork. این ماژول همیشه خوانده می‌شود.

## ۱. چرا
کل پروژه با Claude و Claude Code جلو می‌ره. اگه روش هر کار بعد از تموم شدنش جایی ثبت نشه، دفعهٔ بعد از صفر شروع می‌کنیم. هدف: هر تسکی که تموم می‌شه **خودکار و بدون دستور** روند، متد، ابزار، تصمیم‌ها، تأییدها و درس‌هاش بره تو حافظهٔ مشترک، تا ایجنت و تیم روزبه‌روز سریع‌تر و دقیق‌تر بشن.

درس ۳ آبان: چتی که کانسپت استوری‌های منو توش ساخته شد، با «تو برد آپدیت کن» کار رو کامل نکرد و بخشی از اطلاعات تو برد نیومد. پس ثبت نباید به یادآوری کاربر وابسته باشه.

## ۲. گزارش انجام کار (خودکار، بعد از هر «انجام شد»)
ابزار: `python3 tools/taskreport.py`
- `make <id> --method روند.md --lessons "درس | درس" --tools "…" [--local "E:\…"]` ← گزارش Markdown می‌سازه و می‌ذاره:
  1. مخزن: `kb/tasks/<id>.md` و فهرست `kb/tasks/INDEX.md` (ایجنت، Claude Code و دستیار می‌خونن)
  2. برد: ضمیمهٔ همون تسک با نسخهٔ خوانا (نسخه‌دار؛ ساخت دوباره = نسخهٔ تازه)
  3. ولت: `vault.py ingest` در اجرای بعدی ایجنت برش می‌داره (`tasks/<id>/`)
  4. برندبوک: اگه تسک فصل برندبوک داره، یه خط تو تاریخچهٔ برندبوک
- `pending` ← تسک‌های تموم‌شده‌ای که گزارش ندارن.

**کی می‌نویسه:**
- هر Claude که خودش کاری رو تموم کرد (Claude Code، دستیار، Cowork): همون لحظه، قبل از پیام آخر. روند واقعی رو خودش می‌دونه، پس `--method` و `--lessons` رو کامل بنویسه.
- ایجنت مدیر پروژه در **هر اجرا**: `taskreport.py pending` ← برای هر کدوم (بررسی سریع حداکثر ۳، اجرای کامل همه) از روی کامنت‌ها، تحویل‌ها و تاریخچه روند و درس رو بنویسه و `make` بزنه. اگه روند از برد معلوم نیست، یه سؤال کوتاه روی تسک از مسئولش بپرسه («دو خط بگو چطوری ساختیش و چی یاد گرفتی؟»).
- **روی لپ‌تاپ:** هر محتوا یا کار بصری تو پوشهٔ خودش یه `REPORT.md` داره (پایین، بخش ۶). Claude Code آخر کار همون رو با `--method <مسیر REPORT.md>` به `taskreport.py` می‌ده.

**قالب «روند و متد»** (۴ تا ۸ خط شماره‌دار): ورودی‌ها، مراحل واقعی (با تغییر مسیرها)، ابزار و تنظیمات کلیدی، تأییدها، خروجی و فرمت، زمان واقعی در برابر برنامه.
**قالب «درس‌ها»:** چی جواب داد، چی نه، دفعهٔ بعد چطور سریع‌تر، قاعدهٔ تازه. قاعدهٔ ثابت ← `14-learnings.md` و ماژول تخصصی؛ روش قابل تکرار ← `kb/METHODS.md` (کتابخونهٔ روش‌ها: «چطور X رو می‌سازیم»).
**خط قرمز:** مبلغ، قرارداد، پرداخت، محتوای حساس ولت و توکن هرگز (ابزار جمله‌های مالی رو خودش حذف می‌کنه ولی نویسنده هم مراقب باشه).

## ۳. کلمهٔ رمز: «ثبتش کن» ✅
هر وقت ممضی یا امیرحسین (در هر چت، کامنت برد یا گفتگو) گفت **«ثبتش کن»** یا **«تأییده، ثبتش کن»** یا **«تأییده و ثبت و آپدیت کن»**، یعنی این بسته کامل، بی‌پرامپت اضافه:
1. **پیدا کردن تسک:** تسکی که الان روش کار می‌شه (از عنوان، فایل یا گفتگو). اگه نبود، بساز (با مسئول).
2. **وضعیت:** تسک ← «انجام شد» (یا «در انتظار تأیید» اگه هنوز تأیید امیررضا مونده) در برد اصلی؛ اگه محتواست، مرحله و «منتشر شد» در برد محتوا؛ خط تأیید مربوط تیک.
3. **فایل‌ها:** نسخهٔ نهایی روی تسک (`board.py attach`، با همون اسم برای نسخه‌بندی)؛ فایل عادی هم تو ولت؛ فایل‌های قبلی که عوض شدن روی همهٔ تسک‌های مربوط و «Brand Visual Assets».
4. **گزارش انجام کار:** `taskreport.py make` با روند و درس‌ها (بخش ۲).
5. **دانش:** درس ثابت ← ۱۴ و ماژول مربوط؛ روش ← `kb/METHODS.md`؛ تصمیم تازه ← ۰۵ و `kb/BANK.md`.
6. **برنامه:** تسک‌های بعدی و وابسته (موعد، پیش‌نیاز، شروع)، تقویم محتوا و هر دو برد (`content.py sync`).
7. **بریف‌ها:** `briefNote`/`promptNote` تسک‌های بعدی که به این کار وابسته‌ان.
8. **گزارش‌ها:** اگه به گزارش شبانه یا هفتگی ربط داره، خط «امروز انجام شد» و تأییدهای بعدی؛ `kb/live.md`.
9. **برندبوک:** اگه تسک برندبوکی یا دارایی بصری تازه‌ست، `brandbook.py upsert/log`.
10. **پیام آخر:** یه پیام کوتاه «ثبت شد 👍» + ۳ خط: چی عوض شد، کار بعدی کیه، یه نکته یا ایده.
اگه شِل یا دسترسی push نیست (چت ساده)، همین ۱۰ مورد رو به‌صورت بلوک تحویل بده تا ایجنت اعمال کنه.

## ۴. زوم خودکار روی تسک در حال کار
هر وقت Claude (هر جا) داره روی کاری کار می‌کنه که تو برد تسک داره:
- اول تسک رو پیدا کن و وضعیتش رو «در جریان» کن.
- هر قدم مهم (کانسپت، پیش‌نویس، تغییر مسیر، فایل تازه، تأیید) = یه کامنت کوتاه روی همون تسک، فایل‌ها همون موقع ضمیمه. منتظر «آپدیت کن» نمون.
- آخر کار، حتی بی‌دستور: بستهٔ «ثبتش کن» (بخش ۳)، به‌جز تغییر وضعیت به «انجام شد» که فقط با تأیید یا وقتی کار واقعاً تموم و تأییدشده‌ست.

## ۵. تأیید چهارمرحله‌ای امیررضا (قانون ثابت برنامه‌ریزی)
روند کار ما با امیررضا برای **هر تسکی که خروجی‌اش به امیررضا می‌ره**:
1. **تأیید موضوع**
2. **تأیید ایده و کانسپت اولیه**
3. **تأیید ماکت** (سناریو و استوری‌بورد، رف‌کات، طرح اولیه، نمونهٔ چاپ)
4. **تأیید خروجی نهایی**

قاعده‌ها:
- روی هر تسک چهار خط چک‌لیست: «تأیید امیررضا ۱: موضوع، تا …»، «۲: ایده و کانسپت اولیه، تا …»، «۳: ماکت، تا …»، «۴: خروجی نهایی، تا …». مهلت‌ها از عقب به جلو از موعد چیده می‌شن و زمان انتظار جواب (حداقل یه شب) تو برنامه حساب می‌شه.
- مدیر پروژه برنامه رو **همیشه** با همین چهار گیت می‌چینه: کار مرحلهٔ بعد قبل از تیک مرحلهٔ قبل شروع نمی‌شه، مگه با پیش‌فرض اعلام‌شده («اگه تا ساعت … جواب نیومد، …»).
- تقویم یا جدول تأییدشده = مرحلهٔ ۱ برای همهٔ آیتم‌هاش تیک می‌خوره.
- **گزارش شبانه:** بخش «تأییدهایی که از شما لازم داریم» هر شب برای همهٔ تسک‌های فعال، مرحلهٔ بعدی هر کدوم رو با مهلت می‌آره (گروه‌بندی: موضوع، کانسپت، ماکت، نهایی). جواب‌هایی که امیرحسین ثبت کرد، اجرای بعدی تیک می‌زنه و مرحلهٔ بعد رو باز می‌کنه.
- کارهای داخلی تیم که به امیررضا نمی‌رن (ابزار، برد، فایل کاری) این چهار خط رو ندارن.
